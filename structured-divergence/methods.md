# Method Reference

Read this file completely before selecting methods.

## Core Operators

| Method | Use it to | Do not confuse it with |
| --- | --- | --- |
| Substitute | Replace a concrete element | Modify: change degree or form |
| Combine | Join elements so they interact | Adding unrelated features |
| Adapt | Transfer a known practice while retaining recognizable mechanics | Analogy: borrow an abstract principle |
| Modify | Change scale, intensity, sequence, or form | Extreme Shift: push to a revealing limit |
| Put To Another Use | Give an existing element a different purpose | Adding another benefit |
| Eliminate | Remove a concrete element | Constraint Removal: assume a limiting condition never existed |
| Reverse | Invert a relationship, role, flow, or order | Counterfactual: rewrite an assumed fact |

## Perspective Shifts

| Method | Use it to |
| --- | --- |
| Analogy | Borrow an abstract structural principle without copying the source practice |
| Counterfactual | Change a fact or premise on which the problem depends |
| Constraint Removal | Explore the world where a limiting condition is absent |
| Extreme Shift | Push a variable to an extreme to expose another frame |

## Extensions

Use at most one topic-specific `Extension`, only when the core methods cannot
express the transformation well. Name it and give one sentence about its
purpose.

Add a `Method Note` only for a non-obvious choice. Explain the constraining
assumption and how the method enlarges the space.

Each direction has exactly one primary method. Different labels with the same
underlying transformation are a failure, not diversity.
